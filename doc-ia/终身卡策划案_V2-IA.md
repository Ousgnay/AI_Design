## 1. 业务逻辑摘要

终身卡是一个绑定角色的一次性付费永久权益系统，核心价值由三部分组成：

1. 购买当下给出一次性高感知奖励，如神器自选箱、专属头像。
2. 购买后持续提供每日可领奖励和跨模块长期特权，形成长期登录与留存牵引。
3. 在商坊内作为独立页签呈现，结合未购买、已购买、累计奖励领取、每日奖励领取和特权说明等状态，构成完整权益页。

该系统的 IA 重点不是复杂跳转，而是一个完整的权益说明页加两个标准确认弹窗，再叠加每日领取状态、累计领取状态与跨模块权益摘要。

## 2. 用户流程

**主流程：商坊进入 -> 查看权益 -> 购买 -> 激活 -> 每日领取**

```text
进入商坊
  ↓
切换到「终身卡」页签
  ↓
未购买：查看购买页 / 已购买：查看已激活页
  ↓
点击「立即开通」
  ↓
购买确认弹窗
  ↓
系统支付流程
  ↓
支付成功
  ↓
激活结果页 / 已购买页
  ↓
若存在购买前累计天数 -> 领取累计奖励
  ↓
每日登录后在终身卡页领取当日奖励
```

**分支流程：**

```text
购买前每日登录累计
  ↓
购买后若存在 pre_buy_days
  ↓
显示累计领取入口
  ↓
一键领取累计奖励

已购买用户每日登录
  ↓
产生 pending_reward_days
  ↓
终身卡页出现红点与领取入口
  ↓
一键领取每日奖励
```

|---|---|---|---|---|
| 商坊终身卡页 | 全屏页面 | 商坊页签「商城」/「终身卡」页签切换 | 购买确认弹窗 / 领取入口 / 返回商坊其他页签 | 玩家主动查看终身卡权益 |

## 4. 每个界面的 IA 详情

### 界面 1：商坊终身卡页

**容器**：全屏页面  
**决策依据**：这是一个长期权益总览页，不是短促操作弹窗。页面同时承担页签切换、权益展示、购买状态、累计奖励入口和每日奖励入口，信息密度高，适合全屏承载。

#### 布局区划

| 区域 | 内容 | 信息权重 |
|---|---|---|
| 顶部区 | 商坊顶部页签，包含「商城」与「终身卡」切换 | 高 |
| 主内容区-购买前 | 终身卡核心权益说明：一次性奖励、每日奖励、永久特权、价格与购买按钮 | 极高 |
| 主内容区-购买后 | 已激活状态、今日奖励、累计奖励入口、永久特权摘要 | 极高 |
| 右侧/下部辅助区 | 特权说明、跨模块加成摘要、规则说明 | 中 |
| 红点区 | 页签红点、累计奖励红点、每日奖励红点 | 中 |

#### 状态枚举

| 状态名 | 触发条件 | UI 变化 |
|---|---|---|
| 未购买默认态 | `owned == false` | 显示价格、购买按钮、一次性奖励、每日奖励与永久特权 |
| 已购买默认态 | `owned == true` | 购买按钮置灰，显示已开通状态与当日领取区 |
| 存在累计奖励 | `pre_buy_days > 0` 且 `pre_buy_claimed == false` | 显示累计领取入口与红点 |
| 存在每日可领 | `pending_reward_days > 0` 且 `last_claim_date != today` | 显示一键领取按钮与红点 |
| 月卡联动生效 | 已激活终身卡且持有月卡 | 显示月卡钻石加成说明为生效态 |
| 月卡联动未生效 | 已激活终身卡但未持有月卡 | 显示月卡加成为灰态说明 |

#### Component 清单

| 信息单元 | Component | 变体/属性 | nodeId | 来源 |
|---|---|---|---|---|
| 商坊页签入口 | `icon_c_min` | 商城状态 | `6567:12210` | `component-spec.json -> atomic fallback` |
| 终身卡页顶部主 tab | `二级tab` | 全屏顶部主 tab | `4883:4887` / `4883:4888` | `component-spec.json -> molecular_components` |
| 全屏主内容骨架 | `背包系统/道具页基线` | 用作全屏权益页的左中右分区基线 | `6325:10610` | `layout-spec.json -> frame` |
| 主操作按钮 | `btn_c_lv1_normal_1` | 购买 / 领取主操作 | `4786:929` | `component-spec.json -> atomic fallback` |
| 次操作按钮 | `btn_c_lv1_normal_2` | 取消 / 次级确认 | `4786:926` | `component-spec.json -> atomic fallback` |
| 终身卡状态提示 | `bg_tip_短条` | 规则或状态提示 | `-` | `component-decision.md -> atom fallback` |
| 红点提醒 | 红点系统 | 功能入口未处理提示 | `-` | `component-spec.json -> atomic fallback` |

**决策备注**：  
当前组件库中没有“终身卡专属页”或“商坊权益总览页”的现成组织层组件，页面结构更接近一个全屏权益详情页。主 tab 可直接复用全屏顶部主 tab 分子组件；购买主按钮仍缺 `btn_c_lv1_normal_1` 的精确 `componentKey`，因此下游实例化前需以原子层或同名底板替代。

### 界面 2：购买确认弹窗

**容器**：中弹窗  
**决策依据**：这是标准付费确认场景，内容短、决策明确，需要强打断但不需要整屏承载。`中弹窗空白模板` 已有成熟骨架，适合作为购买确认容器。

#### 布局区划

| 区域 | 内容 | 信息权重 |
|---|---|---|
| 顶部区 | 弹窗标题、关闭按钮、价格提示 | 高 |
| 主内容区 | 终身卡说明、永久绑定角色说明、不可退款提示 | 高 |
| 底部区 | 取消、确认购买两个按钮 | 高 |

#### 状态枚举

| 状态名 | 触发条件 | UI 变化 |
|---|---|---|
| 默认态 | 正常打开弹窗 | 文案与价格完整展示 |
| 支付中 | 用户点击确认后 | 确认按钮置灰，防止重复提交 |
| 支付失败 | 网络或支付渠道异常 | 保持弹窗，显示错误提示 |
| 重复购买拦截 | `owned == true` | 不进入支付流程，按钮置灰或直接提示已开通 |

#### Component 清单

| 信息单元 | Component | 变体/属性 | nodeId | 来源 |
|---|---|---|---|---|
| 弹窗骨架 | `中弹窗空白模板` | 标准中弹窗结构 | `6617:13137` | `component-spec.json -> organism_components` |
| 顶部主 tab / 标题区 | `二级tab` | 标题或切换区占位 | `4919:4384` | `component-spec.json -> molecular_components` |
| 确认购买主按钮 | `btn_c_lv1_normal_1` | 主操作 | `4786:929` | `component-spec.json -> atomic fallback` |
| 取消次按钮 | `btn_c_lv1_normal_2` | 次操作 | `4786:926` | `component-spec.json -> atomic fallback` |
| 关闭按钮 | `btn_c_close_03` | 深色关闭按钮 | `4786:907` | `component-spec.json -> atomic fallback` |

**决策备注**：  
这里优先使用标准中弹窗模板而不是重新组合中小弹窗，因为购买确认虽然内容短，但需要标准确认结构和明确底部操作区。若后续商坊内出现更强交易感确认页，可再升级为专用组织层。

**容器**：中小弹窗  
**决策依据**：激活结果是短反馈场景，但通常会同时展示一次性奖励发放结果、已开通状态和后续入口，因此比纯确认弹窗略复杂，适合中小弹窗模板。

#### 布局区划

| 区域 | 内容 | 信息权重 |
|---|---|---|
| 顶部区 | 成功标题、开通状态标识 | 高 |
| 主内容区 | 一次性奖励发放结果、专属头像、神器自选箱提示 | 高 |
| 底部区 | 返回商坊、立即查看背包、关闭 | 中 |

#### 状态枚举

| 状态名 | 触发条件 | UI 变化 |
|---|---|---|
| 激活成功 | 支付成功且校验通过 | 显示已激活、奖励到账结果 |
| 背包满邮件补发 | 一次性奖励无法直接入包 | 显示邮件提示 |
| 可继续领取累计奖励 | `pre_buy_days > 0` | 在结果页直接展示累计奖励入口 |

### 界面 5：每日奖励领取确认层

**容器**：中小弹窗或页内领取确认区  
**决策依据**：每日领取属于高频动作，必须保持轻量。若放在页面内，可用固定奖励条 + 主按钮；若放到弹窗内，则继续使用中小弹窗空白模板。

#### 布局区划

| 区域 | 内容 | 信息权重 |
|---|---|---|
| 顶部区 | 今日领取状态、未领天数 | 高 |
| 主内容区 | 普通抽卡券、专属抽卡券、累计天数说明 | 高 |
| 底部区 | 一键领取 / 今日已领取 | 高 |

#### 状态枚举

| 状态名 | 触发条件 | UI 变化 |
|---|---|---|
| 今日可领 | `pending_reward_days > 0` 且 `last_claim_date != today` | 按钮高亮，显示可领数量 |
| 今日已领 | `last_claim_date == today` | 按钮置灰显示“今日已领取” |
| 跨日累计 | `pending_reward_days > 1` | 显示 N 天奖励一次性领取 |
| 背包不足 | 领奖前空间不足 | 提示保留奖励，不清零 |

#### Component 清单

| 信息单元 | Component | 变体/属性 | nodeId | 来源 |
|---|---|---|---|---|
| 领取状态条 | `bg_tip_短条` | 状态提示 | `-` | `component-decision.md -> atom fallback` |
| 主按钮 | `btn_c_lv1_normal_1` | 一键领取 | `4786:929` | `component-spec.json -> atomic fallback` |
| 次按钮 | `btn_c_lv1_normal_2` | 今日已领取 / 关闭 | `4786:926` | `component-spec.json -> atomic fallback` |

**决策备注**：  
每日奖励更像页内状态而不是固定弹窗，因此 IA 只定义其信息层级和状态，不强制页面一定弹出独立模态。

## 5. 决策备注

### 5.1 容器选择说明

- 商坊终身卡页采用全屏页面，因为它承担的是一个长期权益总览，不只是购买动作。
- 购买确认使用中弹窗，因为这是标准二次确认。
- 激活结果、累计奖励、每日奖励都属于结果反馈或轻量领取，因此优先使用中小弹窗或页内领取层。

### 5.2 组件复用说明

- `中弹窗空白模板` 与 `中小弹窗空白模板` 都已存在，且分别对应标准中弹窗和中小弹窗骨架，优先复用。
- `UIRewardsPreviewPopUp` 是本案里最适合承载“一次性奖励”和“累计奖励”的组织层组件。
- `背包系统/道具页基线` 可以作为全屏权益页的三段式信息组织参考，但不是严格意义上的终身卡专属 layout。
- `btn_c_lv1_normal_1` 在 `component-spec.json` 中仍缺 `componentKey`，因此 IA 文档保留其 nodeId 级引用，等待后续补采。

### 5.3 软约束偏离说明

- 当前知识库内没有终身卡专属商坊页、专属购买确认页和专属激活页组织层组件，因此部分页面只能采用已有通用模板加语义重组。
- 日奖励区如果后续被产品要求固定在独立弹窗中，可再将其升级为独立 IA 页；当前阶段按页内领取层处理更贴近交互频率。

### 5.4 下游提示

这份 IA 可以直接驱动后续 Figma 实例化，优先顺序建议为：

1. 先做商坊终身卡页的全屏骨架。
2. 再做购买确认弹窗。
3. 最后补激活结果、累计奖励和每日领取层。
