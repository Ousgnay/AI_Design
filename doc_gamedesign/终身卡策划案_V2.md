# 终身卡策划案

> 状态：待确认 | 负责人：主策、模块策划 | 依据：终身卡系统设计文档 v1.0（2026-05-13）

## 一、功能概述与设计目标

### 1.1 概述

终身卡是一次性付费 **168 元** 的永久增值权益卡，绑定角色（非账号）。购买后永久享受每日抽卡道具、玩法次数加成、背包格子扩展、生命之树产出加成等持续权益，同时即时获得神器自选箱子与专属头像。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 提升小R付费 | 168 元一次性到账，解决"不确定玩多久"的决策焦虑 |
| 提升付费留存 | 每日领取机制制造损失厌恶，绑定每日登录行为 |
| 拉动月卡续费 | 月卡钻石 +10% 加成，将终身卡买家转化为月卡续费用户 |

### 1.3 目标用户

累计付费 500～2000 元的小 R 玩家。

### 2.3 一次性奖励

**触发时机：** 购买成功、服务器校验通过后立即发放，无需玩家主动领取。

| 道具 | 数量 | 道具 ID | 背包满处理 |
|------|------|---------|-----------|
| 神器自选箱子 | × 1 | 走配置表 | 邮件发送，保留 30 天，过期销毁 |
| 专属头像 | × 1 | 走配置表 | 邮件发送，保留 30 天，过期销毁 |

> 一次性奖励仅发放一次，不因任何原因补发。

---

### 2.4 购买前登录累计机制

#### 2.4.1 累计逻辑（未购买时）

功能上线后，系统对**所有角色**记录每日登录，与是否购买终身卡无关。

```
每日首次登录时（服务端执行）：
  if owned == false and last_login_date != today:
      last_login_date = today
      pre_buy_days += 1
```

- **开始记录日期由配置表配置**（`lifetime_card_start_date`），上线前填入，运营灵活调整
- 配置日期之前的登录天数不追溯
- 上线日当日登录计为第 1 天
- 天数不过期、不衰减，直至购买后领取

#### 2.4.2 购买后领取入口

购买完成后，若 `pre_buy_days > 0`，在终身卡页面显示累计奖励领取入口：

```
┌─────────────────────────────────────────┐
│  🎁 开通前累计登录 N 天                  │
│  可一次性领取 N 天每日奖励               │
│                                         │
│  · 普通抽卡券 × N                        │
│  · 专属抽卡券 × N                        │
│                                         │
│  ┌─────────────────────────────────┐   │
│  │     一键领取（N 天奖励）          │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

**领取逻辑：**

```
玩家点击「一键领取」：
  检查背包空间（普通抽卡券×N + 专属抽卡券×N）
        │ 不足
        ▼
  提示："背包空间不足，请清理后再领取"
  奖励保留，不丢失（pre_buy_days 不变）
        │ 足够
        ▼
  发放成功 → pre_buy_days = 0 → pre_buy_claimed = true → 关闭此入口
```

若购买时 `pre_buy_days == 0`，不显示此入口。

### 2.5 每日登录奖励

#### 2.5.1 自然日定义

- **日切时间：每日 08:00**（服务器时间）
- 所有日期判断以服务器时间为准，客户端仅做倒计时展示

#### 2.5.2 登录检测（服务端，每次角色登录时执行）

```
if owned == true and last_login_date != today:
    last_login_date = today
    pending_reward_days += 1
```

未登录的自然日不执行此逻辑，该日奖励**永久失效**，无需额外处理。

#### 2.5.4 领取逻辑

```
玩家点击「一键领取」：
  前置检查：
    1. owned == true
    2. pending_reward_days > 0
    3. last_claim_date != today（每日最多领取 1 次）

  N = pending_reward_days

  背包空间检查：
    不足 → 提示"背包空间不足，请清理后再领取"

    足够 → 发放：
           背包 + 普通抽卡券 × N
           背包 + 专属抽卡券 × N
           last_claim_date = today
           pending_reward_days = 0
           按钮切换为"今日已领取"
```

#### 2.5.5 奖励内容

| 道具 | 数量/天 |
|------|---------|
| 普通抽卡券 | × 1 |
| 专属抽卡券 | × 1 |

#### 2.5.6 未领提醒（红点）

| 触发条件 | 红点位置 | 消除条件 |
|----------|---------|---------|
| 已购买 + 当日已登录 + `pending_reward_days > 0` + `last_claim_date != today` | 商坊 → 终身卡页签 | 点击领取成功后 |
| 已购买 + `pre_buy_days > 0` + `pre_buy_claimed == false` | 终身卡页内累计奖励区域 | 领取累计奖励后 |

## 三、玩法特权

### 3.1 昆仑秘境每日免费次数

| 项目 | 原值 | 激活后 |
|------|------|--------|
| 每日免费次数 | 待程序确认 | +1（GDD 规定） |
| 挑战次数储存上限 | 待程序确认 | **9 次**（替换为 9，非叠加） |

| 约束 | 规则 |
|------|------|
| 仅作用于 | 免费挑战次数，不影响付费购买次数 |
| 重置 | 每日 08:00 随日常重置，不累积至次日 |

> 规则结构同涿鹿之争（每日次数 + 储存上限），每日免费次数原始值请程序确认。

---

### 3.2 涿鹿之争每日恢复次数

| 项目 | 原值 | 激活后 |
|------|------|--------|
| 每日自动恢复量 | 6 次 | **8 次**（+2） |
| 挑战次数储存上限 | 28 次 | **30 次**（替换为 30，非叠加） |

| 约束 | 规则 |
|------|------|
| 仅作用于 | 每日自动恢复，不影响道具/钻石购买次数 |
| 重置 | 每日 08:00 随日常重置，不累积至次日 |

---

### 3.3 背包装备格子扩展

| 项目 | 规则 |
|------|------|
| 增加方式 | **固定 +2000 个**（非倍乘） |
| 生效时机 | 购买成功后立即，无需重登 |
| 叠加 | 不叠加（终身卡不可重复购买，自然保证） |

---

### 3.4 月卡每日钻石加成

| 项目 | 规则 |
|------|------|
| 触发条件 | 终身卡已激活 **且** 持有**小月卡或大月卡**（游戏内两类月卡之一即可） |
| 加成公式 | `实际钻石 = floor(月卡原始每日钻石 × 1.1)` |
| 多张月卡 | 每张月卡独立计算，各自 +10% |
| 仅作用于 | 月卡每日持续奖励中的钻石，不作用于月卡一次性奖励 |
| 失效 | 月卡到期即时失效，终身卡本身不受影响 |

**月卡领取界面表现（月卡模块内）：**

```
┌────────────────────────────────────┐
│  月卡每日领取                       │
│                                    │
│  大月卡  基础钻石：  300            │
│          ✦ 终身卡加成：+30         │  ← floor(300 × 0.1)
│          ─────────────────         │
│          今日实际：  330            │
│                                    │
│  [一键领取]                        │
└────────────────────────────────────┘
```

| 场景 | 界面表现 |
|------|---------|
| 已激活终身卡 + 有月卡 | 月卡领取界面显示"终身卡加成 +X 钻"分项 |
| 已激活终身卡 + 无月卡 | 终身卡特权区显示"—（需持有月卡方可生效）" |
| 月卡到期 | 显示"月卡已到期，续费后生效"，加成不计入 |

### 3.5 生命之树果实产出加成

此特权对两类掉落物采用不同规则：

#### 类型 A：装备掉落

```
每次装备掉落时（服务端）：
  if LifetimeCard.IsOwned(roleId):
      if random() < 0.20:   ← 独立判定，与其他概率加成不叠加
          额外掉落 1 件相同装备
```

- 每次装备掉落独立触发一次判定
- 20% 判定与其他概率类加成**相互独立**，不叠加计算

#### 类型 B：其他道具掉落

```
在最终产出时乘以特权系数：
  if LifetimeCard.IsOwned(roleId):
      final_count = floor(base_count × 1.2)
```

- 示例：原 5 个 → 5×1.2=6；原 3 个 → 3×1.2=3.6→ 取整 3
- **执行时机**：在最终产出阶段乘以特权系数（×1.2），与其他加成的相对顺序由程序按"最终产出"节点统一处理

## 四、数据结构

### 服务端持久化字段（角色维度）

| 字段 | 类型 | 初始值 | 说明 |
|------|------|--------|------|
| `owned` | bool | false | 是否已购买 |
| `buy_time` | timestamp | 0 | 购买时间（服务器时间） |
| `pre_buy_days` | int | 0 | 购买前累计登录天数 |
| `pre_buy_claimed` | bool | false | 购买前累计奖励是否已领取 |
| `last_login_date` | string | "" | 最近登录的自然日（YYYY-MM-DD，08:00 为基准） |
| `pending_reward_days` | int | 0 | 已登录但未领取的累计天数 |
| `last_claim_date` | string | "" | 最近一次领取每日奖励的自然日 |

### 客户端展示数据

| 数据 | 来源 |
|------|------|
| 当日可领状态 | 服务器下发 `pending_reward_days` + `last_claim_date` |
| 月卡联动生效状态 | 读取月卡模块激活状态，与 `owned` 做 AND 运算 |
| 累计奖励天数 | 服务器下发 `pre_buy_days`（未领时展示） |
| 当前第几天 | 服务器基于 `buy_time` 计算并下发 |

## 六、边界条件

| 场景 | 处理方式 |
|------|---------|
| 重复购买 | 服务端拦截（`owned == true`），客户端按钮置灰 |
| 购买时背包满（一次性奖励） | 邮件发送，保留 30 天，过期销毁，仅发一次不补发 |
| 累计奖励领取时背包满 | 拦截操作，提示"背包空间不足"，`pre_buy_days` 不清零 |
| 每日奖励领取时背包满 | 拦截操作，`pending_reward_days` 不清零；日切后若未登录不再新增（不豁免过期） |
| 购买当日可领取 | 激活时 `pending_reward_days += 1`，购买后立即可领 |
| 当日未登录 | `last_login_date` 不更新，`pending_reward_days` 不增，该日奖励永久失效 |
| 已登录未领取（跨日） | `pending_reward_days` 保留，次日登录再 +1，可一次性领取 N 天 |
| 每日最多领取 1 次 | `last_claim_date == today` 时拦截 |
| 扣款成功但状态未写入 | 以支付流水为准，由客服介入补发 |
| 服务器宕机无法登录 | 等同未登录，当日奖励不补发 |
| 角色改名 / 转区 | 终身卡随角色 ID 保留，不影响归属 |
| 功能上线前老角色 | 从上线日起计 `pre_buy_days`，不追溯历史 |
| 客户端时间篡改 | 所有日期判断以服务器时间为准，客户端不参与日期计算 |
