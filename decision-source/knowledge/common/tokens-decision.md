# Design Tokens 决策规则

> 来源：Figma 文件「组件 模板 Copy」  
> fileKey: `jB3vJujGbA7pKX9rNIlJUt`

## 1. 适用范围

本文件记录该组件模板文件中的本地 text styles、color styles、effect styles 与已落地 variables，用于后续 IA 推理、界面信息实例化与 Figma 侧 token 对齐。

本次采集目标不是某个单独节点的局部样式，而是整个 file 的 styles 基线。

## 2. Text Styles 规则

当前 file 内共有 4 个 text styles，构成一套偏少但用途清晰的文本层级：

1. `48粗 标题`
2. `42 一级按钮`
3. `38 一级tab、小标题`
4. `34 标准正文`

推理使用建议：

- `48粗 标题`：用于页面主标题、核心标题位，不应用于长段落正文。
- `42 一级按钮`：用于主操作按钮文本，强调点击性与主操作优先级。
- `38 一级tab、小标题`：用于一级 Tab 与区块小标题，承担导航与分区识别。
- `34 标准正文`：用于常规正文、说明文本与通用信息内容。

## 3. Color Styles 规则

当前 file 内共有 17 个 color styles，按底色语境拆成两组：

- `浅色底`：8 个
- `深色底`：9 个

这套规则不是单纯的颜色表，而是“同一语义在不同背景语境下使用不同文字色”的双轨体系。后续推理时，优先先判断背景明暗，再选语义色。

### 3.1 浅色底

适用于浅底卡片、浅底面板、亮底容器上的文字与强调信息：

1. `浅色底/标题1、正文1`
2. `浅色底/标题2、正文2`
3. `浅色底/次级正文`
4. `浅色底/品质-蓝、友军、同盟`
5. `浅色底/品质紫`
6. `浅色底/品质金、重点、阵营、战法、被@玩家`
7. `浅色底/品质红、负面、敌军、地名`
8. `浅色底/正面、玩家本人、地标`

语义规则：

- 标题/正文色按信息层级分为主正文、次正文、弱正文。
- 蓝色承担 `品质-蓝 / 友军 / 同盟` 语义。
- 紫色承担 `品质紫` 语义。
- 金色承担 `品质金 / 重点 / 阵营 / 战法 / 被@玩家` 语义。
- 红色承担 `品质红 / 负面 / 敌军 / 地名` 语义。
- 绿色承担 `正面 / 玩家本人 / 地标` 语义。

### 3.2 深色底

适用于深底面板、深色底纹、暗背景容器上的文字与强调信息：

1. `深色底/标题1、正文1、未输入`
2. `深色底/标题2、正文2`
3. `深色底/正文3、标签、已输入`
4. `深色底/次级正文`
5. `深色底/品质蓝、友军、同盟`
6. `深色底/品质紫`
7. `深色底/品质金、重点、阵营、战法、被@玩家`
8. `深色底/品质红、负面、敌军、地名`
9. `深色底/正面、玩家本人、地标`

语义规则：

- 深底文本层级比浅底多出一档：`标题1/正文1/未输入`、`标题2/正文2`、`正文3/标签/已输入`、`次级正文`。
- `未输入` 与 `已输入` 被显式并入文本层级，说明该文件同时覆盖输入态信息表达。
- 蓝 / 紫 / 金 / 红 / 绿在深底下维持与浅底一致的语义映射，但色值会做提亮处理，以保证对比度。

## 4. Effect Styles 规则

当前 file 内共有 2 个 effect styles：

1. `文本描边`
2. `文本投影`

### 4.1 文本描边

- 实际实现是黑色 `DROP_SHADOW`
- 偏移：`x=0, y=2`
- 模糊：`1`
- 不透明度：`1`

使用建议：

- 主要用于强化高亮标题、较浅文字在复杂背景上的边界可读性。
- 命名虽为“描边”，但实现方式本质上是紧贴型阴影，推理时应按“增强轮廓可读性”理解。

### 4.2 文本投影

- 实际实现是黑色 `DROP_SHADOW`
- 偏移：`x=0, y=2`
- 模糊：`1`
- 不透明度：约 `0.72`

使用建议：

- 主要用于常规文字的轻量投影增强。
- 与 `文本描边` 相比，更偏向柔和层次，而不是强轮廓。

## 5. Variables 规则

当前 file 内共有 2 个本地 variable collections、7 个 variables。

其中一组已具备明确业务语义：

- `关系-敌军`
- `关系-玩家本人`
- `关系-友军`
- `关系-阵营`

这些 variable 的颜色值与浅色底语义色完全对齐，说明本文件内已经存在“关系语义 -> 颜色 token”的雏形。

推理使用建议：

- 若下游目标是信息表达或 IA 语义标注，可优先使用“关系 / 阵营 / 正负面 / 品质”这类语义映射，而不是只记录视觉颜色名。
- 若后续组件无法直接复用 design system 组件，可基于这些 token 进行纯绘制。

## 6. 本次结论

- 该文件的 token 体系重点不在数量，而在“语义色 + 背景语境”的双轨映射。
- 文本层级较精简，适合做移动游戏界面的高密度、强装饰型文字系统。
- 颜色规则已隐含业务语义：关系、阵营、品质、正负面、是否输入。
- effect styles 仅两种，但都明确服务于文本可读性增强。
