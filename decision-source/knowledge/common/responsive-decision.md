# Responsive Decision Rules — 横板2D UI 适配规则

> 来源：Figma「组件 模板 Copy」→ `横板2D-ui适配规范`(`9193:19483`)
> 采集日期：2026-05-19
> 说明：当前来源以规范页、示意图和图片案例为主，尚不适合沉淀为 region 级结构模板；本文件为当前 responsive 规则的权威入口。

## 总则

本项目当前只覆盖 `横屏 2D UI` 的适配规则。

- 设计基准尺寸为 `1920 x 1080`，比例 `16:9`
- 长屏示意基准为 `2340 x 1080`，比例 `19.5:9`
- 平板示意基准为 `1920 x 1440`，比例 `4:3`
- 所有适配判断，优先先判断对象属于：背景、列表、tips、弹窗、条目、或一般 UI 元素
- 不同类型对象采用不同适配方式，不允许用一种缩放规则粗暴套所有界面

## 安全区规则

### 基础安全区

- `1920 x 1080` 基准下，UI 显示安全区为：左 `30`、右 `30`、上 `30`、下 `40`
- 处于 `UI 显示安全区` 内的设计元素允许交互

### 长屏与刘海屏

- 长屏示意稿按 `2340 x 1080` 输出，用于表达 `19.5:9` 机型效果
- 长屏示意中，左右各预留 `100px` 设计安全区用于刘海/异形屏风险判断
- 实际运行时的刘海安全区尺寸应读取具体机型
- 处于 `刘海屏安全区` 的设计元素不可交互

### 平板

- 平板示意稿按 `1920 x 1440` 输出，用于表达 `4:3` 机型效果
- 平板适配不以补黑边为目标，而以保持规则一致和信息完整可读为目标

## 机型与走查基线

当前规范明确给出以下代表机型：

- `Google Pixel`：`1920 x 1080`，`16:9`
- `HUAWEI P30 Pro`：`2340 x 1080`，`19.5:9`
- `iPad`：`1024 x 768`，`4:3`

走查要求：

- 至少覆盖 `16:9`、`19.5:9`、`4:3` 三类比例
- 建议使用 Unity 模拟器插件重点走查 `iPhone XS Max` 与 `iPad 12`
- 若极端比例导致图片模糊，优先排查图片压缩与资源输出问题
- 若资源处理后仍无法解决，再由交互补充针对真实设备的例外规则

## 背景适配规则

### 1. 全屏原画背景

适用场景：

- 背景图以原画形式整屏输出
- 视觉目标是保留完整氛围和中心主视觉，而不是精确复用某块固定容器

核心规则：

- 玩家实机比例在 `[4:3, 21:9]` 范围内时：
  - 若 `实机比例 > 16:9`，按 `定宽` 处理
  - 若 `实机比例 < 16:9`，按 `定长` 处理
- 若 `实机比例 < 4:3`，以 `宽度 a` 为基准缩放背景图，并裁切超出部分
- 若 `实机比例 > 21:9`，以 `长度 b` 为基准缩放背景图，并裁切超出部分

解释：

- `定宽`：以宽度为稳定基准，允许上下裁切
- `定长`：以高度为稳定基准，允许左右裁切
- 超出极值范围后，不再继续依赖常规短屏/长屏推导，而改用更稳的基准边进行裁切

### 2. 纯色 + 纹理类全屏背景

适用场景：

- 背景不是单张原画，而是由纯色、纹理、粒子、渐变、光效等多层组成

核心规则：

- 背景图输出采用 `拆层处理`
- 纯色背景块由搭建侧自行设置为最小可九宫拉伸尺寸
- 纹理、动效装饰在 Unity 中拆为独立节点填充
- 各层根据实际界面效果分别设置对齐方式，不强制同一种缩放策略

### 3. 半屏原画图

适用场景：

- 原画不是背景中心对称铺满，而是与 UI 并列出现
- 原画存在明确视觉重点，且这些重点在不同机型下都必须保持可见

设计要求：

- 原画最大输出尺寸为 `2520 x 1440`
- 在 `1920 x 1080` 短屏尺寸下先定义“绝对可见的核心视觉区”
- 再为长屏 `2520 x 1080` 与平板 `1920 x 1440` 指定实际输出范围
- UI 元素必须做 `上下/左右贯穿` 处理，避免适配后露底或穿帮

横屏适配处理：

- 若 `实机比例 > 16:9`，按 `定宽` 处理
- 若 `4:3 < 实机比例 < 16:9`，按 `定长` 处理
- 若 `实机比例 < 4:3`，以 `宽度 a` 为基准缩放原画，并裁切超出部分

## 元素适配分类

适配一个 UI 元素时，需要至少回答 3 个问题：

1. 它挂靠在哪里
2. 它的位置按什么标尺确定
3. 它的尺寸是否允许变化

### 挂靠逻辑

#### 1. 贴边适配

- 元素无论屏幕尺寸如何变化，始终位于屏幕边缘或角落
- 适合：资源栏、主界面部队头像、系统按钮等

#### 2. 贴内容适配

- 元素无论屏幕尺寸如何变化，始终挂靠在某个内容区内部或附近
- 适合：tips、地表建筑 HUD、部队 HUD 等

### 元素位置

#### 1. 固定像素

- 元素位置由确定的像素值决定
- 适合：边缘功能按钮、状态图标、绝对位置装饰元素

#### 2. 固定比例

- 元素位置由确定的比例数值决定
- 适合：游戏各类弹窗，以及需要保持相对屏幕位置关系的模块

### 元素尺寸

#### 1. 固定大小

- 元素尺寸不随屏幕比例变化
- 该规则适用于绝大多数游戏控件
- 若无特殊理由，不应轻易改变元件原始大小

#### 2. 随屏幕适配

- 元素尺寸随屏幕尺寸变化而拉伸
- 适合：滑动列表底板、容器底板、需要吃满剩余空间的版心框

## 列表适配规则

### 纵向 List

- 纵向布局列表区域随界面 `高度` 拉伸同步变化
- 条目间距不变
- 条目尺寸不变

### 横向 List

- 横向布局列表区域随界面 `宽度` 拉伸同步变化
- 条目间距不变
- 条目尺寸不变

### Grid 列表

#### 非滑动方向固定，滑动方向变化

- 列表的非滑动方向尺寸固定
- 滑动方向长度随适配变化
- 条目间距不变
- 条目尺寸不变

#### 宽高都可变

- 先判断滑动方向
- 只在 `垂直于滑动方向` 的轴上做动态扩容
- 横向场景：布局区域变宽时，优先增加列数，直到单元格宽度触及预设最小宽度
- 纵向场景：布局区域变高时，优先增加行数，直到单元格高度触及预设最小高度
- 若无法继续增加行/列，则固定当前数量，并把剩余空间平均分配给当前所有单元格
- 目标是：单元格尺寸保持统一，并尽可能填满布局区域

## 条目适配规则

- 列表沿 `滑动方向` 拉伸填充
- 在 `垂直于滑动方向` 的轴上，条目在内容框内 `居中对齐`
- `内容框` 指条目适配区域，其尺寸先在 `1920 x 1080` 基准下定义，再随界面整体拉伸自适应

## Tips 适配规则

### 屏幕坐标系 Tips

- 必须始终完整显示在 `UI 安全区` 内
- 出现位置应尽量靠近点击位置
- 若靠近边界，应自动调整到安全区内，而不是允许溢出

### 世界坐标系 Tips

- 位置基于游戏世界坐标系
- 会随着镜头移动而变化
- 允许被屏幕边缘裁剪

### 通用交互规则

- tips 在点击位置附近出现
- 点击任意非面板区域可关闭
- 调整镜头高度时关闭
- 拖拽时不关闭
- tips 打开时不屏蔽其他按钮交互

## 弹窗适配规则

### 悬浮弹窗

- 与屏幕四边无直接贴边关系
- 在屏幕内保持居中
- 当前规范强调 `上下居中对齐`

### 全屏弹窗

- 背景图覆盖全屏
- 背景图适配遵循背景规则
- 弹窗内信息层按元素自身的贴边 / 贴内容 / 固定像素 / 比例 / 拉伸规则处理

### 通屏弹窗

- 背景图横向贯穿屏幕左右
- 背景图设计宽度按 `2520` 输出
- 高度可按具体业务自定义
- 弹窗容器与内容在屏幕内 `居中对齐`

### 侧弹窗

- 左侧贴边或右侧贴边出现
- 水平按左/右边缘对齐
- 垂直方向按上下拉伸或上下对齐处理

## 长屏穿帮规避

- 若设计存在贴边元素，长屏状态下该元素应延伸到短屏可视范围之外
- 当前规范给出的经验值为：左右延伸 `280px`，上下延伸 `180px`
- 目标是避免长屏下背景或边缘装饰露出未覆盖区域

## 使用顺序

1. 先判断对象属于背景、列表、tips、弹窗、条目，还是普通元素
2. 再判断它的挂靠逻辑：贴边还是贴内容
3. 再判断它的位置标尺：固定像素还是固定比例
4. 最后判断它的尺寸策略：固定大小还是随屏幕适配
