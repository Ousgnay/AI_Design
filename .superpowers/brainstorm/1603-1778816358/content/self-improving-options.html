self-improving 与 ia-generate 的关系

核心问题：谁拥有决策源的写权限？

A

共享目录 + CLAUDE.md 注册路径

决策源放在独立的 decision-source/ 目录，CLAUDE.md 统一注册该路径。ia-generate 只读，self-improving 读写。两个 Skill 解耦，通过约定路径通信。

优

  • 职责纯粹
  • 扩展性好
  • 符合 D8 精神

劣

  • 需要 CLAUDE.md 严格维护路径
B

ia-generate 子命令（推荐）

将学习能力做成 ia-generate 的子命令：ia-generate improve。决策源由 ia-generate "拥有"，self-improving 的逻辑编写在 ia-generate skill 内部，自然访问所有资源，无需跨 Skill 路径。

优

  • 零耦合风险
  • 决策源所有权清晰
  • 与 figma-design-spec 的 learn 子命令设计一致

劣

  • ia-generate 体量变大
C

完全独立 Skill（但依赖路径约定）

self-improving 独立，但在 SKILL.md 里硬编码 ia-generate 的资源路径。实现最简单，但引入跨 Skill 硬耦合。

优

  • 开发最快

劣

  • 违反 D8（路径硬编码）
  • ia-generate 重构时必须同步改 self-improving
📐 架构事实
ia-generate 的决策源（decision-source/）是整个系统的核心知识库。它既是 ia-generate 的"燃料"，也是 self-improving 的"目标"。谁拥有这个目录的写权限，直接决定了两个 Skill 之间的依赖方向。
方案 B 是推荐方向：ia-generate 既是"使用者"又是"维护者"，逻辑自洽，self-improving 的名称成为 ia-generate 的一个模式，而非独立实体。
