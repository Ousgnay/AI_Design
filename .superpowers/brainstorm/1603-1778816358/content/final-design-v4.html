④ Phase 验证标准

Phase 1 — 核心流验证
构建步骤：清空旧文件 → decision-source 目录 → CLAUDE.md → ux-collect SKILL.md → ia-generate SKILL.md
验证方式：输入一个真实策划需求，跑完整链路，人为评估 Figma 界面产出质量
评估点 1 — 决策源 → IA 文档质量：ia-generate 产出的 IA 文档是否准确反映业务逻辑
评估点 2 — Layout 准确性：界面容器选择、信息层级、布局区划是否合理
评估点 3 — Component 引用准确性：尤其是 component，能复用的是否正确引用已有组件，未命中的是否按 token 绘制
出口：三个评估点均达到"可接受"，进入 Phase 2
Phase 2 — 学习闭环验证
构建步骤：self-improving SKILL.md
验证方式：使用 同一个真实策划需求，经过 self-improving 学习后重新跑链路
评估点 — Phase 1 中记录的 bad case，在本次产出中是否被有效避免
出口：同类 bad case 有明显减少，说明学习闭环有效
