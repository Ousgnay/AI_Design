旧架构 vs 新架构

XGame AI 设计工作流 — 系统性重构前的认知对齐

❌ 旧架构（TGame时代，8个Skill）
输入层
策划文档 → planning-doc-to-tasks
Figma竞品页 → figma-competitive-extractor
↓
规范层
figma-design-spec → rules/common + rules/specific
↓
原型层（三轨）
web-prototype-builder → HTML原型
figma-design-builder → Figma原型
↔ figma-web-bridge（手动桥接）
↓
验收 + Unity
workflow-auditor + unity-csharp-spec
⚠️ 问题：8个Skill职责交叉 / figma-design-builder vs Plan B官方Skill主权不明 / 缓存层不可行 / 路径全是TGame
✅ 新架构（XGame，4个环节 + 3个Skill）
环节1：业务逻辑输入
策划MD（必选）+ 竞品拆解MD（可选）
↓
环节2：信息架构IA处理
ia-generate skill
决策源：流程推理 / 容器选择 / 信息层级 / 状态枚举 / Component决策
约束：hard（强制）/ soft（参考）
格式：JSON数据集 + MD决策链
输出：IA结构化文档.md
↓
环节3：信息实例化
官方Figma Skill包（figma-use / figma-generate-design）
输出：Figma Frame（能复用的component严格引用，不能复用的按token凭空绘制）
↓
环节4：自我学习
self-improving skill
输入：人类反馈（会话/Figma批注）
处理：AI复盘 → bad case归纳 → 人工审批 → 更新决策源
ux-collect skill（横切）：采集Figma规则/案例 → 补充IA决策源
🔑 核心变化
废弃
• web-prototype-builder（去掉HTML原型）
• figma-design-builder（执行交给官方）
• figma-web-bridge（无双轨）
• figma-competitive-extractor（并入ux-collect）
• planning-doc-to-tasks（并入ia-generate）
重组为3个Skill
• ux-collect（采集决策源）
• ia-generate（IA推理）
• self-improving（自我学习）
+ 官方Figma Skill包（执行层）
