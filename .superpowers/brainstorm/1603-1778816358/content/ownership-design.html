知识库归属设计

核心问题：knowledge/ 放在哪里，三个 Skill 才能无耦合地各自读写？

A

knowledge 放在项目根目录（推荐）

decision-source/ 是项目资产，不属于任何 Skill。三个 Skill 都是访问项目资产的工具，CLAUDE.md 统一注册路径。

[项目根]/
  decision-source/        ← 项目资产，中立
    knowledge/
      common/             ← ux-collect 写
      specific/           ← ux-collect 写
    learnings/           ← self-improving 写
.claude/skills/
  ia-generate/          ← 只读 decision-source/knowledge/
  ux-collect/           ← 写 decision-source/knowledge/
  self-improving/       ← 读写 decision-source/
  unity-csharp-spec/    ← 独立
  workflow-auditor/     ← 独立

优

  • 零跨 Skill 耦合
  • 三者都是平级独立 Skill，用户可独立触发
  • ia-generate 天然只读（物理路径隔离）
  • CLAUDE.md 统一注册路径，符合 D8 精神

劣

  • knowledge 不在 .claude/ 内，显得"游离"
B

knowledge 放在 .claude/ 内的共享目录

在 .claude/ 下建一个独立的 knowledge/ 目录（不属于任何 Skill），三个 Skill 通过 CLAUDE.md 注册路径访问。

.claude/
  knowledge/            ← 共享数据层
    common/
    specific/
    learnings/
  skills/
    ia-generate/
    ux-collect/
    self-improving/
    unity-csharp-spec/
    workflow-auditor/

优

  • 所有东西都在 .claude/ 内，整洁
  • 同样零耦合

劣

  • .claude/ 内 knowledge 和 skills 平级，结构稍混
📌 两方案的权限约定（CLAUDE.md 注册）：

ux-collect：写 knowledge/common/ 和 knowledge/specific/
self-improving：读 knowledge/（比对现有规则）+ 写 learnings/ + 批准后更新 knowledge/
ia-generate：只读 knowledge/（不可写）
