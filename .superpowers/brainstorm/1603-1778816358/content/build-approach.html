整体构建路径

XGame 新架构从零开始，两种推进节奏

A

核心流先跑通，学习环后补（推荐）

分两阶段：先把主干闭合，验证 IA 产出质量；再接入学习闭环。

Phase 1：主干（优先）
1. 清空 XGame 旧文件，建立新目录结构
2. ux-collect Skill — 从 Figma 采集决策源
3. ia-generate Skill — 读决策源 → 产 IA 文档
4. 端到端跑一个真实界面（如城市主界面）
Phase 2：学习环 + 配套（Phase 1 验证后）
5. self-improving Skill — feedback → bad case → 更新决策源
6. workflow-auditor Skill — 验收审计
7. unity-csharp-spec Skill — C# 规范产出

优

  • 主干先验证，问题早暴露
  • Phase 1 完成即可投入真实使用

劣

  • Phase 2 有等待期
B

5 个 Skill 一次性全建

同步建好全部 5 个 Skill 的骨架和 SKILL.md，一次完成脚手架，再逐步填充内容。

一次性完成
建目录结构 + 5 个 SKILL.md 骨架 + CLAUDE.md + decision-source/ 初始文件
优：结构一次到位；劣：内容还是要逐步填，验证时间更长，风险更集中

优

  • 架构全貌一次成型，团队可并行认知

劣

  • 5 个 Skill 同时开工，验证周期长，问题晚暴露
